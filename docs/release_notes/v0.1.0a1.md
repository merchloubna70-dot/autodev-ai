## What is autodev-ai

autodev-ai is a multi-CLI software factory that turns a one-paragraph brief, a GitHub issue, or a bug description into milestone-driven delivery artifacts. A 12-agent CrewAI pipeline (InputClassifier → PRDWriter → SystemArchitect → MilestonePlanner → TaskDecomposer → ExecutorRouter → QualityGate → SecurityReviewer → Verifier → DocWriter → ReleaseManager) routes code-writing work to Codex CLI (scaffolds, small patches, tests) or Claude Code CLI (architecture, multi-file refactors, security review, release roll-up) through a single `ExecutorRouter`. When neither CLI is present, a deterministic `MockExecutor` takes over — useful for demos and CI. Every run writes a structured artifact tree under `<repo>/.dev-factory/runs/<run_id>/`, is resumable and replayable, and is gate-protected: `release_check` returns `NotReleaseReady` whenever mock execution or dry-run mode was used.

## 5-minute quickstart (zero API keys required)

The mock executor path produces realistic structured artifacts without any API keys or CLI installations.

```bash
# Step 1 — install (wheel or source; see above)
autodev --help   # verify install

# Step 2 — run the demo project in dry-run + mock mode
autodev deliver-project \
  --project-brief examples/01-mdlines/brief.md \
  --from-scratch true \
  --mode dry-run \
  --executor auto \
  --allow-mock-executor true \
  --repo-path /tmp/mdlines-demo

# Step 3 — explore what was produced
ls /tmp/mdlines-demo/.dev-factory/runs/*/delivery/
cat /tmp/mdlines-demo/.dev-factory/runs/*/delivery/final_report.md
```

Expected terminal output:

```
[autodev] --scale not given; will auto-infer from PRD/brief
run_id=20240514-143012-a1b2c3 mode=dry-run mock=True release=NotReleaseReady
```

`release=NotReleaseReady` is the correct and expected result here. See the **Mock fallback warning** section below.

See [docs/quickstart.md](../quickstart.md) for the full annotated walkthrough including artifact directory layout.

## Key capabilities

- **35 CLI subcommands** covering the full delivery lifecycle from `classify-input` through `release-check`, `sprint-start`, `roundtable`, `mcp-serve`, and `a2a-serve`; every command ships `--help` documentation.
- **41 CrewAI agents** (44 agent modules) spanning `InputClassifier`, `ProductManager`, `PRDWriter`, `SystemArchitect`, `MilestonePlanner`, `TaskDecomposer`, `QualityGate`, `SecurityReviewer`, `Verifier`, `DocWriter`, `ReleaseManager`, and specialist A2A cards.
- **17 orchestration flows** mapping the agent graph to concrete pipeline stages (project delivery, issue pipeline, bug fix, sprint, roundtable, release check, and more).
- **MCP server** (`autodev mcp-serve`) — 9 tools over JSON-RPC 2.0 / stdio; compatible with Claude Desktop and Claude Code.
- **A2A protocol** — HTTP + local-shell transports for agent-to-agent task dispatch; roundtable party-mode fans out to N specialist agents and synthesizes a consensus report.
- **BMAD sprint mode** — `sprint-start` / `sprint-status` / `sprint-retro` / `sprint-correct` for multi-week sprint planning and mid-sprint course correction; `design-ux` for BMAD-Sally UX workflows.
- **Multi-CLI executor router** — `ExecutorRouter` selects Codex CLI, Claude Code CLI, or MockExecutor per task based on task type, risk level, and file count; `--executor auto` (default) or explicit override.
- **4-stage bug-fix flow** — `fix-bug` runs Reproduce → Locate → Patch → Verify, each stage producing a structured JSON artifact; `multi-patch-fix-bug` generates N patch candidates and votes for the best.
- **Multi-patch self-consistency** — `multi-patch-fix-bug` produces N independent patch candidates via separate executor invocations and selects the winner by structural agreement, not a single noisy sample.
- **Full audit trail** — every run writes a deterministic artifact tree under `<repo>/.dev-factory/runs/<run_id>/`; runs are resumable (`continue-run`) and replayable (`replay`).

## MCP / A2A note

**MCP server** — `autodev mcp-serve` starts a JSON-RPC 2.0 server over stdio. Register it in Claude Desktop or Claude Code by adding the following to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "autodev": {
      "command": "autodev",
      "args": ["mcp-serve"]
    }
  }
}
```

Available tools: `autodev_scan`, `autodev_classify_input`, `autodev_create_prd`, `autodev_deliver_project`, `autodev_run_issue`, `autodev_report`, `autodev_roundtable`, `autodev_release_check`, `autodev_list_runs`.

**Dual-gate apply guardrail** — tools that write files (`autodev_deliver_project`, `autodev_run_issue`) require `mode=apply` in the request **and** the environment variable `AUTODEV_MCP_ALLOW_APPLY=1` set in the server process. Both gates must be open simultaneously; either alone is not sufficient. Default (`mode=dry-run`) produces planning artifacts only, writes nothing to the target repo.

**Audit log** — set `AUTODEV_MCP_AUDIT_LOG=/path/to/audit.jsonl` to append an HMAC-signed record of every tool invocation.

**A2A** — `autodev a2a-serve` opens a JSON-RPC 2.0 HTTP server for external agent tasks. `autodev roundtable` fans out a topic to N specialist cards (architect, security, performance, ux, style) and synthesizes a consensus. The HTTP transport blocks RFC-1918 / loopback by default; set `AUTODEV_A2A_ALLOW_PRIVATE_NETWORKS=1` to override for local testing only.

## ExecutorRouter note

`ExecutorRouter` is the single choke point for all CLI traffic — no business code calls `codex` or `claude` directly.

| Condition | Backend selected |
|---|---|
| `--executor codex` (explicit) | Codex CLI |
| `--executor claude` (explicit) | Claude Code CLI |
| `--executor auto` + task is scaffold / test / small feature | Codex CLI |
| `--executor auto` + task is architecture / refactor / security / release | Claude Code CLI |
| Either CLI absent and `--allow-mock-executor true` | MockExecutor (deterministic) |

**No-API-key mode** — pass `--allow-mock-executor true` (or set `FACTORY_FORCE_MOCK=1`) to engage the mock executor path. Artifacts are produced instantly and deterministically, but `release_check` will return `NotReleaseReady`. This mode is intended for demos, CI pipelines, and local exploration — not for generating real code changes.

## Known limitations

- **Alpha API** — CLI flags, pipeline artifact schemas, and inter-agent contracts may change in 0.1.0a2 or 0.2.0 without a deprecation cycle. Do not build production integrations against this release's internal APIs.
- **Homebrew tap not yet available** — the formula exists at `packaging/homebrew/Formula/autodev-ai.rb` but is explicitly blocked (`sha256 "TODO_PUBLISH_SHA256"`) until PyPI publish completes and the real sha256 is confirmed. See `packaging/homebrew/PUBLISH_CHECKLIST.md`. Do not attempt `brew install autodev-ai`; it will fail.
- **Production or enterprise use is not supported** — egress sandboxing, per-caller MCP authentication tokens, signed Docker images, and SBOM generation are not in scope for this release. The security hardening in R2/R3 meaningfully reduces attack surface but does not constitute a complete network sandbox.
- **Real Codex / Claude CLI execution** — planning and dry-run flows work reliably; task-level execution with real CLI binaries may require project-specific sandbox tuning (working directory, environment variable scope, shell restrictions) and has not been validated across all project types.
- **macOS `.app` launcher** — signed and notarized status of any `.app` wrapper has not been validated for this release.
- **A2A HTTP transport** (`a2a-http` card transport) is future work; remote HTTP agent dispatch is not yet implemented. Current transports: `mock` (stable) and `local-shell` (stable).
- **MCP long-running tools** (`autodev_deliver_project`, `autodev_run_issue`) execute synchronously in v1; JSON-RPC `notifications/progress` streaming is not yet implemented.

## Security notes

The R2 + R3 hardening rounds addressed the following:

1. **SSRF guard** (R2) — A2A HTTP transport rejects requests targeting RFC-1918 addresses, loopback (`127.x`, `::1`), and link-local ranges by default.
2. **DNS rebinding protection** (R3) — A2A server validates the `Host` header to reject browser-originated DNS rebinding attempts.
3. **MCP apply guardrail** (R3) — write-mode tool invocations require two independent gates (`AUTODEV_MCP_ALLOW_APPLY=1` + `allow_apply=true` in the request).
4. **WorkerIsolator shell blocklist** (R3) — subprocess executor blocks a configurable set of dangerous shell patterns in all modes, including mock.

These controls harden the attack surface for typical development machine usage. They are **not** a complete network sandbox and have not been independently audited. Do not expose `autodev a2a-serve` or `autodev mcp-serve` on untrusted networks without additional network-level controls.

## Mock fallback warning

When `--mode dry-run` and `--allow-mock-executor true` are both active (or `FACTORY_FORCE_MOCK=1` is set), every CLI invocation is replaced with a deterministic fixture response. The artifact tree is structurally complete — PRD, architecture doc, task list, quality gate, final report — but the content is fixture data, not real LLM output. `release_check` detects this and returns `NotReleaseReady` unconditionally. A completed dry-run artifact tree is not evidence that real code changes were produced.
