## What's new

### Supply-chain provenance (3 supply-chain commits)

- **cosign keyless image signing** on every tag push — `ghcr.io/merchloubna70-dot/autodev-ai` images carry detached Fulcio OIDC signatures recorded in the Rekor transparency log. Verify with:
  ```bash
  cosign verify ghcr.io/merchloubna70-dot/autodev-ai:v0.1.0a4 \
    --certificate-identity-regexp='https://github.com/merchloubna70-dot/autodev-ai/.+' \
    --certificate-oidc-issuer=https://token.actions.githubusercontent.com
  ```
  See `docs/release/cosign_verification.md`.
- **SLSA L3 provenance attestation** via `slsa-framework/slsa-github-generator`. Every wheel/sdist now ships with an `in-toto` `.intoto.jsonl` attestation backed by GitHub Actions OIDC; verifiable independently of CI logs with `slsa-verifier`. See `docs/release/slsa_verification.md`.
- **SBOM workflow** (carried from a3, now exercised end-to-end) — CycloneDX 1.5 (`sbom.cdx.json`) and SPDX 2.3 (`sbom.spdx.json`) attached to every Release; consumable by grype, trivy, syft. Supports EU CRA / US EO 14028 toolchains. See `docs/release/sbom_consumption.md`.

### MCP per-caller authentication

The MCP server (`autodev mcp-serve`) now supports per-caller identities with scope-based authorization. Set `AUTODEV_MCP_IDENTITIES=path/to/identities.json` to activate; each caller gets a hashed token and a scope set (`mcp:read` / `mcp:write` / `mcp:apply`). Apply mode is now a **triple gate**:

1. caller identity carries `mcp:apply` scope
2. server has `AUTODEV_MCP_ALLOW_APPLY=1` in env
3. request flag `allow_apply=true`

Audit log entries gain a `caller_id` field. Fully backward compatible: unset `AUTODEV_MCP_IDENTITIES` keeps the existing single-token / open-stdio behavior (audit records `"legacy_shared_token"`). See `docs/mcp_server_per_caller_auth.md`.

### CI hygiene

- New composite action `.github/actions/setup-autodev/action.yml` is the single source of truth for the CI Python environment. Previously both `test.yml` and `lint.yml` duplicated `pip install -e ".[dev,tui]"`, which drifted twice during a4 development.
- `actions/setup-python` v5 → v6 (resolves Node.js 20 deprecation that GitHub enforces 2026-06-02).
- `actions/checkout` left at v4; `docker/login-action` v3 → v4; `docker/build-push-action` v5 → v7; `docker/setup-qemu-action` v3 → v4; `softprops/action-gh-release` v2 → v3.

### Fixes

- `tui/dashboard.py`: `action_quit` is now `async` to match `textual.App` override semantics. The lax CI mypy (`--ignore-missing-imports`) hadn't caught this; the strict mypy run inside the release-readiness gate did.

## Verification

After install, verify integrity:

```bash
# 1. PyPI wheel + SLSA attestation
slsa-verifier verify-artifact autodev_ai-0.1.0a4-py3-none-any.whl \
  --provenance-path autodev_ai-0.1.0a4-py3-none-any.whl.intoto.jsonl \
  --source-uri github.com/merchloubna70-dot/autodev-ai \
  --source-tag v0.1.0a4

# 2. Docker image signature
cosign verify ghcr.io/merchloubna70-dot/autodev-ai:v0.1.0a4 \
  --certificate-identity-regexp='https://github.com/merchloubna70-dot/autodev-ai/.+' \
  --certificate-oidc-issuer=https://token.actions.githubusercontent.com

# 3. SBOM (attached to GitHub Release)
gh release download v0.1.0a4 -p 'sbom.*.json' --repo merchloubna70-dot/autodev-ai
```
